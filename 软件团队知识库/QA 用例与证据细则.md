# 验证与验收判据细则（Test Rubrics）

QA 侧的用例设计、证据留存与报告结构细则。与软件团队知识库 物理验收判据.mdQA 任务表的关系：那张表是 PM 核验你交付的判据，本文是你生产这些交付的操作标准——两文配套，验收未过先查本文是否执行到位。安全要求本体只在软件团队知识库 安全与日志审计基线.md 维护，本文只写"用例怎么设计、证据长什么样"，不复制条款。

## 一、用例设计总则

1. **契约驱动**：用例清单在只拿到冻结契约 + Tech Spec 时必须已经能写完。先读实现再补用例 = 独立性丧失（review-criteria"独立性"判据直接打回）。
2. **编号规范**：`TC-{TASK-ID}-{三位序号}`（如 `TC-AUTH-005-012`），全报告唯一；同一契约错误码的用例编号写进覆盖对账表，PM 按 code 反查。
3. **自包含**：每条用例声明前置状态（角色、租户、种子数据），可独立执行，不依赖前一条用例的副作用；环境重置步骤写进复现说明。
4. **断言期望值的唯一来源**：正向断言对契约 `examples`（`mock_gen.py` 产物）逐字段，错误断言对 `x-error-codes` 的 `http_status` + `code` 两层，行为断言对 `trigger` / `x-permissions` / `x-audit` 声明文本。实测与期望不符时改的是被测物或契约，永远不是断言。

## 二、功能覆盖矩阵（逐 operation 过一遍）

| 类别 | 用例来源 | 断言要点 |
| --- | --- | --- |
| 正向路径 | 每个 operation 的 2xx 样例 | Result 包装 `code=0`；字段名与样例逐字一致；ID 类字段是字符串；分页样例含 `pageNum`/`pageSize`/`total` 且与种子数据量一致 |
| 错误路径 | `x-error-codes` 登记表**逐 code** 构造 | 按 `trigger` 文本造触发条件；HTTP 状态 = `http_status` 映射，业务码 = `code`，两层都断；`message` 无堆栈/SQL/内部路径（契约标准 §8.4） |
| 入参校验 | requestBody/parameters 的 schema 约束 | 必填缺失、类型错、长度边界（max、max+1）、枚举越界、format 非法——直接 HTTP 请求打服务端，不经过前端；命中即 4xx 登记码，不允许 500 |
| 边界与并发 | 契约显式声明的机制 | 乐观锁 `version` 冲突 → 409 类（启用才测）；重复提交的幂等表现按 Tech Spec 声明验证；未声明的不造题 |

错误码覆盖率 100% 是硬门槛（与 lint E011 同源：登记表每个 code 至少一条用例），做不到就在报告结论分布里如实写 FAIL，不许静默跳过。

## 三、安全用例细则（基线 §八 QA 义务的执行标准）

每条用例除接口响应断言外，凡涉及日志与审计的，必须延伸到落盘原文摘录——这是 review-criteria"脚本查不出的走人工判据"里 QA 负责供证的部分。

| 族 | 用例设计 | 通过判据 |
| --- | --- | --- |
| 垂直越权 | 对每个带 `x-permissions` 的 operation：更高角色清单外的低角色调用 + 匿名调用 | 返回契约登记的 403 类错误码；响应形态与"资源不存在"一致，不泄漏资源存在性；"已登录"不等于有权限（基线 AC-4） |
| 水平越权 | 同角色跨用户、跨租户取/改他人资源：把路径或入参中的资源 ID 换为他租/他人的 | 同上拒绝；换 ID 探测的批量枚举用例至少 1 条；服务端查询带租户与属主条件才可能通过——只靠前端隐藏的实测必 FAIL |
| 鉴权绕过 | 无 Token / 伪造签名 / 已过期 / 登出后旧 Token / 他人 Token 五连；微服务拓扑加"绕过网关直连服务端口" | 全部 401 类（登出后失效是 ID-2 的显式要求）；直连被内部令牌校验拒绝 |
| 登录失败处理 | 连续错密至锁定阈值 → 锁定期内正确口令也被拒 → 未到期解锁请求 → 到期后成功；成功后计数清零；Token 过期即拒 | **阈值数字只用 Tech Spec 拍板值**；未拍板则降级为机制存在性验证（会锁、过期真拒），报告标注"阈值断言待总架构师拍板"，禁止拿基线示例值（5 次/15 分钟）当判据 |
| 脱敏 | grep 运行日志与审计 `detail` 落盘原文：口令/完整 Token 任何形态不得出现；`x-sensitive` 标注字段按 DP-3 统一打码形态断言 | 摘录命中位置（文件:行）；出现原文即 FAIL，附上下文；接口响应回显口令/Token 字段同样断言（契约 §8.2 禁止响应含 `writeOnly` 字段） |
| 审计覆盖 | 对每个 `x-audit` 声明：成功触发 → 检索八要素齐备、`event_type`/`object` 与声明一致；`on_fail: true` 的构造失败分支（越权/校验拒绝）→ 有记录且 `outcome=fail` 附错误码；登录/登出接口 → LOGIN_SUCCESS/LOGIN_FAIL/LOGOUT 事件在位 | 检索方式按 Tech Spec 声明的落点（落库查表 / grep 审计文件）；事件清单对账表逐条有证据，缺一条即覆盖率不足；审计与业务日志物理混写按基线"留存与形态"节 FAIL |
| 错误外泄 | 构造可造的 5xx 场景（依赖服务关停等）→ 响应仅兜底码 + traceId | 造不出 5xx 时降级为配置审查：引用开发 S008 门禁输出 + 异常处理器位置，在报告如实标注"N-A（造题不可行），证据=配置审读" |

安全用例的批次结论不因功能全绿而豁免：越权/绕过任一缺执行记录，本批次 QA 报告按未完成自报，不等 PM 打回。

## 四、结论分级

| 结论 | 适用 | 处置 |
| --- | --- | --- |
| PASS | 实测与契约期望一致 | 落日志进报告 |
| FAIL | 实测偏离契约，期望值无歧义 | 开发缺陷候选：报告列期望-实测差异 + 证据；**不判定"可接受偏差"** |
| BLOCKED | 契约缺口 / 前置未满足 / 期望值本身待拍板 | 上报 PM 转 architect 或总架构师；附缺口原文，不猜测 |
| N-A | 场景构造不可行（如 5xx 造不出） | 必须写降级验证方式与理由，空 N-A 按未执行处理 |

实现与契约冲突时：记录双方原文（契约段落 + 实测报文），结论给 FAIL，处置权在 PM 与总架构师——你在报告里不写"实现更合理"之类的裁定语。

## 五、证据与日志标准

1. **执行日志三要素**：命令原文、时间戳、退出码。汇总行保持 pytest / vitest / jest / surefire 标准格式（PM 侧 `check_testlog.py` 只认这四种）。
2. **一用例一可定位记录**：日志中每条用例结果行携带用例编号，报告摘录能过 `check_excerpt.py` 逐字回溯；FAIL 与重试的日志都留存，删除失败记录等同伪造（`developers/README.md` 五节红线）。
3. **落盘位置**：执行日志 `qa/logs/TC-*.log` 或按批次 `qa/logs/{task}-*.log`；用例工程与脚本 `qa/tests/`，种子数据 `qa/fixtures/`——全部相对项目 `root_dir`，在任务卡 `outputs` 声明。
4. **复现性**：报告附一键重跑说明（命令 + 种子数据 + 环境变量清单，变量只写名与用途、不写值）；复跑结果与报告矛盾 = 报告作废。

## 六、测试报告结构（`qa/reports/{task-id}-{scope}-report.md`）

```markdown
# {TASK-ID} 测试报告：{范围描述}
- 契约基准：path + version + sha256（开工前重算比对结果：一致）
- 执行摘要：PASS n / FAIL n / BLOCKED n / N-A n；总用例数；通过率
- 覆盖对账表：operation × 用例编号 × 结论（正向 / 错误码逐 code / 安全族逐 x-permissions、x-audit、x-sensitive 条目）
- 失败详情：每条 FAIL → 期望（契约位置）/ 实测（日志摘录）/ 证据路径
- BLOCKED 与上报事实：缺口描述 + 双方原文 + 上报去向
- 复现说明：重跑命令、fixtures 路径、环境要求
- 自检凭证：check_outputs / check_testlog 输出（退出码与报告路径）
```

## 七、QA 红线（命中即打回，不接受解释）

- 读了实现代码再"对齐"断言，或为让用例通过而修改期望值
- 拿"开发单测已 100% 绿"替代自己的集成/安全用例执行
- 错误码覆盖率、安全用例族任何一项缺失而未在报告中自报
- 用基线示例值或未拍板参数当断言判据
- 使用真实用户数据、连生产库、把真实凭据写进用例或日志
- 删除/裁剪失败日志，重试后只留绿色记录
- 在报告里对契约-实现冲突作合理性裁定
