# 安全与日志审计基线（等保二级 · 开发侧）

**本文是全项目安全与审计要求的唯一权威来源。** 各角色 prompt、各技术栈 skill、review-criteria 只指回本文，不重复条款——重复即漂移。

## 一、适用范围与级别声明

| 项 | 约定 |
| --- | --- |
| 定级基线 | **等保二级**（GB/T 22239-2019 第二级安全要求）为全项目默认基线 |
| 更严要求 | 行业或地方法规更严时**从严**（如重要数据处理场景日志留存 ≥1 年）；升三级须总架构师裁定后另开基线版本 |
| 本文管什么 | 应用代码、接口契约、库表、日志与制品里**开发可落地**的控制项 |
| 本文不管 | 物理环境、网络边界设备、云平台配置、安全管理制度与人员——由运维与安全负责人承担，开发侧只需保证"可被审计、可被管控"的接口存在 |
| 法条锚点 | 《网络安全法》第二十一条第（三）项：采取监测、记录网络运行状态与网络安全事件的技术措施，**留存相关网络日志不少于六个月** |

**开发侧交付定义**：功能实现 + 上述控制项落地 + 门禁脚本真实通过，三者缺一不视为完成。

## 二、身份鉴别

来源：等保二级 · 安全计算环境 · 身份鉴别 a)/b)/c)

| 编号 | 要求 | 开发落地 |
| --- | --- | --- |
| ID-1 | 登录用户身份标识**唯一**，鉴别信息有**复杂度要求并定期更换** | 账号唯一约束；口令策略（长度 ≥8，含大小写+数字+符号中三类，90 天轮换）在服务端强制校验，不依赖前端；历史口令不可复用 |
| ID-2 | 具备**登录失败处理**：限制非法登录次数、结束会话、连接超时自动退出 | 失败计数 + 锁定（如 5 次锁 15 分钟，Redis TTL）；Token 有效期与刷新策略显式配置；登出即失效（服务端黑名单/会话撤销） |
| ID-3 | 远程管理时防止**鉴别信息被窃听** | 口令只走 HTTPS；登录接口禁止把口令写进任何日志（含请求体日志）；禁用基本认证进业务接口 |

补充（本项目自定，非国标条款）：禁止共享账号、禁止默认口令账号存在（对应访问控制 b)）；机器间调用用密钥/证书而非人用账号。

## 三、访问控制

来源：等保二级 · 安全计算环境 · 访问控制 a)/b)/c)/d)

| 编号 | 要求 | 开发落地 |
| --- | --- | --- |
| AC-1 | 为登录用户分配账户与权限 | 每个接口在契约里显式声明所需角色；无声明 = 未授权 |
| AC-2 | 重命名/删除默认账户，修改默认口令 | 初始化脚本禁止插入 `admin/admin123`；种子账号首次登录强制改密 |
| AC-3 | 及时删除或停用多余、过期账户，避免共享账户 | 停用即拒绝（状态校验在鉴权环节，不在业务分支里）；提供账号禁用接口与审计 |
| AC-4 | 最小权限，管理用户权限分离 | 权限点粒度到"资源 + 操作"，不做 `*` 通配授权；平台管理员与租户管理员职责分离 |
| AC-5 | **越权防护（本项目重点）** | 垂直越权：每个 admin 接口做角色校验；水平越权：**每条查询/写入都带租户与属主条件**，禁止只靠前端隐藏入口 |

前端路由守卫与按钮隐藏只算 UI 体验，**不构成访问控制**；真实判定只在服务端每次请求发生。

## 四、安全审计（日志审计要求）

来源：等保二级 · 安全计算环境 · 安全审计 a)/b)/c)

| 编号 | 要求 | 开发落地 |
| --- | --- | --- |
| AU-1 | 启用安全审计，**审计覆盖到每个用户**，覆盖重要用户行为与重要安全事件 | 见第五节事件清单，接口与事件类型一一对应，无遗漏 |
| AU-2 | 审计记录包括**日期和时间、用户、事件类型、事件是否成功**及其他相关信息 | 固定八字段结构（下节），字段名与来源不得随意改 |
| AU-3 | 对审计记录进行**保护、定期备份**，避免未预期的删除、修改或覆盖 | 审计日志独立文件/表，只增不改；应用账号无 DELETE/TRUNCATE 权限；写入失败不得静默吞掉（fail 即告警）；纳入备份计划 |

### 审计记录八要素（每条必须齐备）

下列为**逻辑字段名**（落库列名沿用此 snake_case）；各技术栈的线上形态按各自惯例映射，如后端 JSON 输出用 camelCase（`auditId`/`eventTime`…），映射表见 `skills/springboot-scaffold/references/security-audit.md`。**键的语义与集合不得增删**，改名要走基线变更。

```
audit_id      雪花 ID（出参字符串）
event_time    时间戳，服务器统一 NTP 同步，带时区
actor         { userId, username, tenant, role, is_sys_tenant }，未登录事件记 anonymous
event_type    枚举：LOGIN_SUCCESS / LOGIN_FAIL / LOGOUT / PERMISSION_DENIED /
              DATA_CREATE / DATA_UPDATE / DATA_DELETE / DATA_EXPORT /
              AUTH_ISSUE / CONFIG_CHANGE / SECURITY_BLOCK / AUDIT_TAMPER
object        被操作资源类型 + 资源 ID（如 question:1234567890）
outcome       success | fail，并附错误码（与契约 x-error-codes 同源）
client        { ip, userAgent, traceId }
detail        脱敏后的变更摘要（字段级 old→new，禁止全量快照与明文敏感值）
sign          记录级摘要（HMAC 或链式 hash prev_sign），用于检测篡改
```

### 留存与形态

- **运行日志与审计日志物理分离**：不同文件/不同表、不同 appender；审计日志不混在业务 INFO 里。
- **留存 ≥180 天**（法定六个月为下限），日志滚动策略按此配置；行业更严者从严。
- 审计内容里的个人信息一律**先脱敏后落盘**；原文不出现在任何运行日志。
- 必须可按 用户 / 时间区间 / 事件类型 / 资源 检索并导出（供等保测评与应急响应）。
- 时间源统一（NTP），跨服务用 `traceId` 串联，保证事件可还原成一条时间线。

## 五、数据保护与个人信息

| 编号 | 要求 | 开发落地 |
| --- | --- | --- |
| DP-1 | 数据分类分级，重要数据备份与加密（网安法二十一条（四）） | 表与字段标级；鉴别数据、重要个人信息**存储加密或散列**；口令只存 BCrypt 类散列，禁止可逆加密 |
| DP-2 | 传输保密性 | 对外一律 HTTPS/TLS；服务间敏感调用走内网 + 内部令牌，禁止明文透传口令 |
| DP-3 | 展示与日志脱敏 | 手机号 `138****0000`、身份证/银行卡保留首末、口令与 Token **完全不落**；统一脱敏工具，禁止各处手写 substring |
| DP-4 | 个人信息最小化 | 仅采集业务必需字段；新增采集需走变更流程并由总架构师确认告知同意口径 |
| DP-5 | 剩余信息与删除 | 注销/删除请求有实现路径（软删要说明依据），密钥/临时凭据不写内存常驻缓存 |

## 六、入侵防范与代码安全

来源：等保二级 · 安全计算环境 · 入侵防范 a)–d)，其余为项目自定基线

| 编号 | 要求 | 开发落地 |
| --- | --- | --- |
| SEC-1 | **数据有效性检验**：人机接口与通信接口输入必须符合系统设定 | 服务端 `@Valid` + DTO 约束为唯一防线；白名单校验（枚举、正则、长度、范围），不做"前端已校验"假设 |
| SEC-2 | 注入 | SQL 只走参数化/MyBatis `#{}`；`${}` 仅限白名单拼接并注释说明；禁止字符串拼 SQL |
| SEC-3 | 文件上传 | 类型白名单 + 大小限制 + 重命名存储 + 禁止可执行目录 + 下载鉴权（禁越权直链） |
| SEC-4 | 反序列化与外部引用 | 禁 fastjson autotype；对外部 URL 走 SSRF 白名单；XML 解析关闭外部实体 |
| SEC-5 | 错误信息不外泄 | 响应体不含堆栈、SQL、内部路径、密钥；系统级异常统一 50001 + traceId |
| SEC-6 | 最小安装与暴露面收敛 | 依赖只加必需项；`management.endpoints.web.exposure.include` 只留 `health,info`；关闭默认目录列表与调试页面 |
| SEC-7 | 依赖漏洞 | SBOM/漏洞扫描进 CI 门禁（后端如 `dependency-check`、前端 `npm audit --omit=dev`），高危未处置不得提测 |
| SEC-8 | 前端侧 | 禁未过滤的 `dangerouslySetInnerHTML`；Token 存内存/短时效，长期凭据不落 `localStorage` 明文；控制台禁止打印用户数据 |

## 七、机检门禁项（可脚本校验，命中 ERROR 即打回）

| 编号 | 检查 | 级别 | 执行者 |
| --- | --- | --- | --- |
| S001 | 硬编码机密（口令/密钥/token/内网 IP/namespace UUID） | ERROR | `check_secrets.sh` |
| S002 | SQL 字符串拼接、MyBatis `${}` 未白名单说明 | ERROR | `check_security.sh` |
| S003 | 口令明文比较或明文存储（`equals` 比对密码字段、可逆加密） | ERROR | `check_security.sh` |
| S004 | 日志/审计里打印口令、完整手机号、身份证、Token | ERROR | `check_security.sh` |
| S005 | 审计能力缺失（工程内无审计事件写入实现） | ERROR | `check_security.sh` |
| S006 | 审计日志滚动/留存配置 < 180 天 | ERROR | `check_security.sh` |
| S007 | actuator/CORS 过度暴露（`include: *`、`allowed-origins: "*"`） | ERROR | `check_security.sh` |
| S008 | 响应体回显异常栈或 `getMessage()` 透出 | WARN | `check_security.sh` |
| S009 | 依赖高危漏洞 | ERROR | CI 扫描步骤 |

## 八、职责分工

| 角色 | 安全义务 |
| --- | --- |
| 总架构师（用户） | 定级与升档裁定、密码/锁定/留存等参数阈值拍板、双因素是否纳入 |
| architect | 契约里显式 `security` 与角色要求；敏感字段标注；错误码设计不泄漏内部信息；把本文条款映射进 Tech Spec。契约侧的声明形态见 `api-contract-spec.md` 第八节，**该节不在 contract_validator 的机检范围内**，靠自检清单 + PM 登记前对账 |
| 开发智能体 | 按技术栈 skill 实现控制项；交付前跑本栈门禁脚本并留存完整输出（后端 S001–S010，前端 F001–F008，含 `.sql` 或数据源配置变更时另跑 D001–D015）；缺实现不上线，无理由豁免按未完成处理 |
| QA | 越权、鉴权绕过、脱敏、审计覆盖率的用例设计与证据留存（判据见 `review-criteria.md`） |
| PM | 核验门禁凭证真实性；安全判据缺项即打回；破坏性安全变更走裁定流程 |

## 九、待总架构师拍板的参数（本文留白，不得由开发自行假定）

1. 口令复杂度与轮换周期具体值（本文明示为示例：≥8 位、三类字符、90 天）
2. 登录失败锁定阈值与时长（示例：5 次 / 15 分钟）
3. Token 有效期与是否引入刷新机制
4. 审计日志留存天数（法定下限 180 天，是否按行业上调至 1 年 / 3 年）
5. 是否要求双因素鉴别（等保三级才强制，二级不要求；若业务涉敏感资金/医疗数据建议纳入）
6. 审计记录落库还是落文件（落库需给出只增权限的库账号方案）
