# 软件团队知识库 · 总索引

> 本知识库是软件开发智能体小分队的规范权威。文件名即文档名；角色三件套写「查阅知识库《文档名》」，绑定本知识库的 Waker 自行检索。
> 运行层提示：门禁命令中的物理路径（如 `--schema` 参数、技能脚本路径）是运行时参数，指向本机克隆仓库，不属知识引用。

## 文档清单

| 文档 | 内容 | 主要使用角色 |
| --- | --- | --- |
| 任务字段标准 | 任务六要素与生命周期字段标准（含 JSON Schema 全文与逐字段说明） | PM |
| 任务状态机 | 任务状态与流转边的权威定义；账本归属 R1-R4 设计决策与已知缺口 | PM（成员不读状态判定） |
| 任务派发模版 | 派发卡形态（含 JSON 示例全文） | PM |
| PRD 模版 | 需求文档权威形态：§三 两栏澄清台账、§五 待拍板、§十二 DoD | PM 产出；architect 引用 §四/§五/§七 |
| Tech Spec 模版 | 技术规格书权威形态：§七 待拍板参数表；节号是跨角色引用锚点 | architect |
| 接口契约标准 | OpenAPI 契约结构与错误码规范；§八 安全与审计声明形态 | architect 产出；PM 登记对账；QA 用例真源 |
| 安全与日志审计基线 | 等保二级基线，安全与日志审计唯一权威；第九节为待拍板参数 | 全角色只指回，不复制条款 |
| 开发者通用技术规范 | 六条铁律、开工规范、报告骨架、红线、注释标准 | 程序员（各栈通用底线） |
| QA 用例与证据细则 | 覆盖矩阵、安全用例判据、结论分级、复现要求 | QA |
| 物理验收判据 | PM 验收的通过/打回判据与证据要求 | PM；QA 交付前自查 |

## 引用口径

- 角色三件套与知识库互相引用一律写《文档名》，不写物理路径。
- 《任务字段标准》《任务派发模版》原文为 JSON；本知识库收录同名 `.md` 说明件（含 JSON 全文与字段说明）。机检用的物理 JSON 在本机仓库 `软件团队知识库/` 下（运行层），门禁命令按物理路径取用。
- 《任务状态机》的「已知缺口」一节按仓库原样保留；其中「无执行器」缺口在 QoderWake 形态由 WakerFlow 补位（见 `../wakerflow/`），其余缺口仍然有效。
