# 任务字段标准

> 检索说明件：本文件是知识库检索用适配稿，原文为 JSON Schema（运行层物理文件：本机仓库 `软件团队知识库/任务字段标准.json`）。门禁命令 `task_tracker/validate.py --schema` 按物理路径取用原 JSON；本文件供角色理解字段口径。

## 概要

任务分派与生命周期标准。**派发六要素**：`task_id` / `goal` / `complexity` / `inputs` / `outputs` / `acceptance_criteria`；`assigned_to` 与 `status` 等生命周期字段由 PM 统一维护（单写者原则）。状态机权威定义见《任务状态机》。

## 逐字段说明

| 字段 | 类型/约束 | 说明 |
| --- | --- | --- |
| `task_id`（必填） | string，格式 `^[A-Z][A-Z0-9]*-[0-9]{3}$` | `{项目前缀}-{三位序号}`，如 AUTH-001；项目前缀在全账本内唯一 |
| `assigned_to`（必填） | 枚举 | `human`（总架构师，承担技术决策与破坏性变更拍板）/ `architect`（架构设计与契约产出）/ `backend-java`、`backend-python`、`backend-rust`、`frontend-react`、`desktop-tauri`（按技术栈划分）/ `qa`；PM 只分派与验收，不执行任务 |
| `goal`（必填） | string，非空 | 一句话陈述可量化目标 |
| `complexity`（必填） | 枚举 S / M | T-Shirt 定级；**L 级强制二次拆解，禁止直接派发** |
| `status`（必填） | 枚举 | `TODO` / `IN_PROGRESS` / `IN_REVIEW` / `ACCEPTED` / `REJECTED` / `BLOCKED`；流转边以《任务状态机》为准 |
| `inputs`（必填） | string 数组 | 前置任务产物与冻结契约的物理路径，相对项目 `root_dir`；上游任务须全部 ACCEPTED 且契约已登记冻结方可派发 |
| `outputs`（必填） | string 数组，≥1 项 | 要求的物理产出物路径，相对项目 `root_dir`；验收时逐一核验存在且非空 |
| `acceptance_criteria`（必填） | string 数组，≥1 项 | 绝对判据：测试覆盖要求、无报错日志、静态检查通过等 |
| `rejection_history`（必填） | 数组，初始空 | 打回历史；每次 REJECTED 追加一条（`round` / `rejected_at` / `reason` / `evidence` ≥1 条）；同一问题同一原因超过 2 次向用户报警 |
| `accepted_at`（可选） | date-time | 验收通过时间，仅 status 为 ACCEPTED 时存在 |
| `verification_log`（可选） | string | PM 验收对账记录 |
