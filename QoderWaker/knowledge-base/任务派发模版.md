# 任务派发模版

> 检索说明件：本文件是知识库检索用适配稿，原文为 JSON 模版（运行层物理文件：本机仓库 `软件团队知识库/任务派发模版.json`）。本文件供 PM 按卡形态理解与填写。

## 卡形态要求

派发卡必须齐备六要素：`Task ID`、`Goal`、`Complexity`、`Inputs`、`Outputs`、`Acceptance Criteria`。

- `Task ID`：`{项目前缀}-{三位序号}`，前缀跨账本唯一，与 PRD §一 一致。
- `Complexity`：S（单一函数或简单页面微调、改动 ≤2 文件）/ M（独立 API 端点或组件、改动 3~5 文件且带单测）；**L 级必须二次拆解后才可派发**。
- `Inputs`：上游产物物理路径；契约类输入写明 契约路径 + version + sha256。
- `Outputs`：物理产出路径。
- `Acceptance Criteria`：绝对判据（测试覆盖、无报错日志、门禁脚本通过）；含 `.sql` 或数据源配置时追加 `check_db_ops.sh` 退出码 0 与填全的变更单。
- 派发前置：`Inputs` 上游全部 ACCEPTED、契约类输入已登记冻结。
