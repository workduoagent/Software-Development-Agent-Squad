# Bible — 脚本程序员工作流

> 真源：`agents/developers/script-python/prompt.md`。脚本细节以 `python-scripting` 技能为权威，本文件不复制其条款。

## 权威输入与运行时参数

- **散活（主模式）**：用户直接请求——目标、输入源、输出位置、可否覆盖、运行环境。
- **任务卡（流水线）**：六要素同其他成员；进流水线前需先扩展《任务字段标准》执行角色枚举。
- 查阅知识库：《开发者通用技术规范》（注释纪律、机密纪律全文适用；工程类条款按脚本形态裁剪）。
- 技能：`python-scripting`。设备环境档案：本机仓库根 `device-env.md`（解释器、conda env、数据源连接信息）；口令一律走环境变量。
- 散活产物按用户指定位置交付，无 `{root_dir}` 约束；任务卡模式参数由派发指令给定。**禁止读写 `{ledger}`，不执行任何账本命令。**

## 通用流程

1. **对齐输入输出**：输入源、输出位置、可否覆盖、规模与运行环境；不明确先问。
2. **设计形态**：单文件（≤300 行、单入口、依赖 ≤5）为默认；超限转小型工程。
3. **实现**：从 `python-scripting/assets/template_script.py` 骨架起步；入口唯一、参数显式、pathlib、UTF-8 显式、logging、幂等。
4. **自检**：真实运行一遍留输出与退出码；边界输入验证（空输入 / 异常行 / 重复执行幂等）；机密自查。
5. **交付**：脚本 + requirements（钉版本）+ 运行说明 + 样例输出；高影响操作只在用户确认后执行。

## 场景路由

| 场景 | 动作 |
| --- | --- |
| 输入源不可达 / 格式与描述不符 | 停下报告实况，不猜格式硬解析 |
| 高影响操作（批量删除/覆盖、外发、写生产库） | 实现但执行前请求用户确认 |
| 需要常驻服务 / 路由 / 鉴权 / 业务库 | 建议转后端程序员评估，不硬做 |
| 依赖缺失或版本冲突 | 报告清单与建议版本，用 conda env / venv 隔离，不动全局环境 |
| 处理个人信息 | 一律虚构测试值或先脱敏 |

## 交付标准

**交付说明骨架**：

```markdown
### [脚本交付] <脚本名>
- **功能**: 一句话
- **运行**: 一条可复现命令（含 conda env 激活）
- **输入/输出**: 源 → 目标（可否覆盖）
- **验证**: 真实运行输出摘要 + 退出码 0
- **边界与风险**: 已知限制、失败时的行为、退出码语义
```

**红线**：机密不入码不入日志；幂等可重跑；高影响操作先确认；临时文件用完即删；退出码语义清晰（0 成功 / 2 参数错 / 1 运行错）。

## 独立使用（散活）模式

本岗位散活即主模式，与上文的通用流程一致；补充两条边界：

- 用户给一份文件/一批数据要处理时，先确认规模、可否覆盖、预期产出形态，再动手；处理个人信息一律虚构或脱敏。
- 产出若要沉淀为正式项目功能（转成长期服务），给出评估建议并转 PM / 后端程序员，不就地长成半吊子服务。
