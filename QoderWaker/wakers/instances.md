## 使用模式（每个实例都具备）

- **流水线模式**：经 WakerFlow / 任务卡派发，执行门禁与账本纪律（成员不碰账本）。
- **散活模式**：用户直接对话处理非项目事务——PM 拆需求/排期/评估、成员可行性评估与实现方案、脚本工具、前后端联调；不碰账本，产物按用户指定位置交付，安全红线不放宽。散活产出升级为正式项目时走 PM 立项进 S0。

## 装配步骤

**先建 7 个角色模板**：按「角色模板表单字段」建模板并上传对应 `roles/<模板>/` 三件套；模板级不挂栈技能（pm / architect / qa 可挂各自技能，程序员四类模板保持为空，栈技能全部在实例挂载）。

**再建 Waker 实例**：

1. **角色模板**：按「实例划分表」列选择——react-dev-01 / vue-dev-01 共用「前端程序员」；java-dev-01 / py-backend-dev-01 / rust-dev 共用「后端程序员」；tauri-dev-01 用「桌面程序员」；py-script-dev-01 用「脚本程序员」。
2. **名称与描述**：Waker 名称填实例名；「我负责什么」照抄上表实例描述（取自对应 prompt.md 现成 description）。
3. **运行环境**：本机（当前设备）。换设备需重配凭证与本地依赖。
4. **Skills**：按上表「实例级技能」在实例上挂载。上传来源见 `../skills/README.md`。
5. **知识库**：绑定同一个知识库（上传方法见 `../knowledge-base/README.md`）。
6. **连接器**：暂无必需项。
7. **设备环境**：把 `device-env.template.md` 复制到本机仓库根改名 `device-env.md` 并按实况填写（已进 `.gitignore`；口令只记环境变量名）。

## 装机后核验

- **栈身份不串**：向 java-dev-01 提问「你的岗位与挂载技能」，应答出后端程序员 / JDK 21 + Spring Boot 3 与 springboot-scaffold、database-ops，且不提前端栈规范；向 py-backend-dev-01 同理（FastAPI 线）。
- **改派检查**：把一条 Web 页面任务描述丢给 tauri-dev-01，应退回要求改派而非硬接；把桌面任务丢给 react-dev-01 同理。
- **散活可用**：直接给 py-script-dev-01 一个数据处理请求（无任务卡），应走散活流程交付脚本 + 运行说明 + 退出码证据，全程不提账本。
- **评估可用**：直接给 java-dev-01 一个「能不能实现、怎么实现」问题，应产出评估骨架（结论/依据/方案/风险/工作量），选型标注归总架构师拍板。
- **PM 单例**：全环境只有 pm-01 一个实例挂 task_tracker 且允许写 `tasks.json`。
- **成员不知账本**：向任一成员实例问账本路径，应答「不读写账本，状态由 PM 负责」。
- **知识库命中**：向 architect-01 问「契约标准第八节是什么」，应能检索《接口契约标准》并答出 §八 安全与审计声明要点。
- **环境档案**：向任一成员实例问「本机 JDK/Node 版本」，应答取自 device-env.md；问口令，应答走环境变量、不出现明文。
